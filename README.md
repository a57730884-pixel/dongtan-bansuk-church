# 동탄반석교회 홈페이지

설계서(`Bansuk_Church_Website_Design_1.docx`)의 1·2단계를 실제로 돌아가는 화면으로 만든 것입니다.
공개 홈페이지는 **사랑의교회(sarang.org)의 디자인을 기준**으로 맞췄고,
**교적관리와 재정관리는 운평장로교회(k-logos.com)에서 쓰고 있는 모듈을 그대로 가져와**
반석교회 전용으로 바꿔 놓았습니다.

### 디자인 기준 (sarang.org 실측값을 그대로 적용)

| 항목 | 값 |
|---|---|
| 서체 | Noto Sans KR 한 가지 (명조 섞지 않음), 본문 17px/1.6, 자간 −0.02em |
| 글자색 | 제목 `#191919` · 본문 `#333` · 보조/영문부제 `#9499A3` · 메뉴 `#343F52` |
| 강조색 | `#02368C` (링크·버튼) |
| 배경 | 흰 `#FEFEFE` → 연회색 `#F6F7F9` → 연파랑 `#EDF2FC` 를 띠처럼 교차 |
| 헤더 | 흰 배경 고정, 높이 95px(모바일 64px), 대메뉴 가운데, 오른쪽 원형 아이콘 로그인 버튼 |
| 컨테이너 | 1320px, 카드 모서리 8px, 썸네일 16:10 |
| 카드 | 썸네일 → 분류 → 한글 제목 → **영문 부제(회색)** → 날짜 |
| 섹션 | 왼쪽에 큰 제목, 오른쪽에 '자세히 보기 ›' |
| 그 외 | 히어로 아래 겹치는 바로가기 카드 줄, 어두운 말씀 띠, 오른쪽 아래 맨 위로 버튼 |

색·문구·사진은 모두 반석교회의 것으로 새로 만들었습니다(사랑의교회의 로고·사진·글은 쓰지 않았습니다).

### 오늘의 큐티

큐티 **본문**은 `js/config.js` 의 `QT_SOURCE` 가 가리키는 곳에서 읽어 옵니다.
복사해 두지 않으므로 원본이 고쳐지면 화면도 함께 고쳐집니다.

큐티 **기록**(누가 언제 아멘 했는가)은 이 교회 데이터베이스에 남습니다.

밖에서 온 글이므로 화면에 넣기 전에 문단·강조·목록만 남기고
스크립트와 속성은 모두 떼어 냅니다(`js/qt.js` 의 `clean()`).

큐티 **음성**은 이미 만들어져 있는 낭독 음원을 씁니다. 파일 이름이 낭독 텍스트의
지문으로 정해지므로, `js/qt-audio.js` 는 그 텍스트를 글자 하나까지 같은 방식으로
조립합니다 — 손대면 음원을 못 찾습니다. 없는 날은 기기 음성으로 읽어 줍니다.

### 로그인 · 회원가입 동의 절차

운평장로교회(k-logos.com)의 가입 흐름을 바탕으로, 「개인정보 보호법」 제15조·제22조에 맞추어
필수와 선택을 나눈 단계형 동의로 다시 지었습니다.

| 단계 | 화면 | 내용 |
|---|---|---|
| ① | 약관 동의 | 전체 동의 + 항목별 동의. [필수] 이용약관 · 개인정보 수집·이용 · 만 14세 이상, [선택] 교회 소식 받기. 항목마다 **보기** 를 누르면 수집 항목 · 이용 목적 · 보유 기간이 그 자리에서 펼쳐집니다. |
| ② | 정보 입력 | 이름 · 이메일 · 비밀번호(8자 이상) · 비밀번호 확인. 무엇에 동의했는지 요약이 함께 보이고 **고치기** 로 ①로 돌아갑니다. |
| ③ | 가입 완료 | 가입 확인 메일 안내. 메일의 링크를 눌러야 로그인됩니다. |

- 동의한 항목과 시각은 `signUp` 의 user_metadata 로 넘어가, 데이터베이스 트리거가
  `profiles`(현재 상태)와 `consent_logs`(덧붙이기 전용 장부)에 나누어 기록합니다.
  장부는 수정·삭제 권한을 주지 않아 고칠 수 없습니다.
- 선택 동의(교회 소식)는 **나의 기록** 화면의 *개인정보 동의 내역* 카드에서 본인이 직접 켜고 끕니다(제37조).
- 동의문 문구는 `js/layout.js` 의 `CONSENTS` 배열 한 곳에만 있으며, `privacy.html` 본문과 같은 내용이어야 합니다.
  문구를 고치면 `CONSENT_VERSION`(= 방침 시행일)도 함께 올려 주세요.

### 관리 영역 — 운평에서 이식한 부분
| 파일 | 내용 | 접근 |
|---|---|---|
| `care.html` + `js/care.js` | **목회 행정** — 성도별 성경 읽기 진행률 대시보드(참여 인원 · 최근 이레 · 진행률 막대) | 최고관리자 |
| `gyojeok.html` + `js/gyojeok.js` | **교적관리** — 권한 관리 · 교적 명단 · 가정 카드 · 가계도 · 교적 추가/수정/삭제(보관)/복원 | 담임목사(관리자) |
| `finance.html` + `js/finance.js` | **재정관리** — 전표 입력(헌금·지출·엑셀 일괄) · 거래장부 · 헌금자 통계 · 총계정원장 · 월/연 결산 · 예산 대비 집행 · 기부금영수증 발급과 대장 · 설정 | 관리자 + 재정권한자 |
| `js/finance-api.js` | 위 두 화면이 쓰는 데이터 계층(Supabase 어댑터) | — |

> 이식하면서 바꾼 것은 세 가지뿐입니다.
> ① 교회 이름·주소·대표자 등 인쇄물에 찍히는 정보를 `js/config.js` 의 `window.CHURCH` 로 분리,
> ② 실행 조건을 구글 Apps Script(`FINANCE_API_URL`) 대신 Supabase 설정 여부로 변경,
> ③ 파일 업로드를 Cloudflare R2 대신 **Supabase Storage** 로 변경(`js/upload.js`).
> 화면 동작과 계산 로직은 운평에서 쓰던 그대로입니다.

장 단위 mp3 가 없거나 열리지 않으면 기기에 들어 있는 음성으로 대신 읽어 줍니다.

## 3. 켜는 순서 (한 번만)

**0단계 · 계정** — 교회 전용 구글 계정을 새로 만들고, 그 계정으로 Supabase·Vercel·유튜브를 개설합니다.
(설계서 3.1 — 제작자 계정에 묶이면 사람이 바뀔 때 사이트가 사라집니다.)

**1단계 · 데이터베이스 연결**
1. [supabase.com](https://supabase.com) 에서 프로젝트를 만듭니다.
2. Project Settings ▸ API Keys 의 **Project URL** 과 **publishable key**(`sb_publishable_…`) 를 복사합니다.
3. `js/config.js` 의 `PROD` 칸에 두 값을 붙여 넣습니다. 같은 파일 맨 위의 교회 정보(주소·전화·대표자·계좌)도 채웁니다.

**2단계 · 표 만들기**
Supabase ▸ SQL Editor 에서 `supabase/01 → 02 → 03 → 04 → 05 → 06 → 08 → 09 → 10 → 11 → 12 → 13` 을 차례로 Run 합니다.
(07 은 관리자 등록용이라 3단계에서 따로 실행합니다.)

**3단계 · 관리자 등록**
1. 관리자가 되실 분이 홈페이지에서 회원가입하고, **가입 확인 메일의 링크까지 누릅니다.**
   (링크를 누르기 전에는 계정이 만들어지지 않습니다.)
2. SQL Editor 에서 `supabase/07_admin.sql` 을 열어 맨 위의 이메일만 바꾸고 Run 합니다.
   UID 를 복사할 필요 없이 이메일로 찾아 넣고, 끝나면 현재 관리자 목록을 보여 줍니다.
3. 새로고침하면 상단에 **교회 행정** 메뉴가 나타납니다.

> `admins` 에 들어가면 교적·재정을 포함해 모든 문이 열리며, 이 표 안에서는 등급 차이가 없습니다.
> 관리자를 더할 때마다 같은 파일의 이메일만 바꾸어 다시 Run 하면 됩니다.

**4단계 · 교적 올리기**
```bash
python tools/gyojeok_xlsx_to_sql.py "교적.xlsx" supabase/교적_등록.sql
```
만들어진 `supabase/교적_등록.sql` 을 SQL Editor 에 붙여넣고 Run 합니다.
(완성본이 아니어도 됩니다 — 있는 만큼 올리고 나머지는 교적관리 화면에서 채우면 됩니다.)

**5단계 · 재정 시작**
재정관리 ▸ 설정에서 회계연도 시작월과 전기 이월금을 정하고,
계정과목을 교회 장부에 맞게 손본 뒤 전표를 입력하거나 엑셀로 한 번에 올립니다.

**6단계 · 배포**
GitHub 저장소에 올리고 Vercel 에 연결하면 끝입니다(정적 사이트라 빌드 설정이 없습니다).
도메인은 Vercel ▸ Domains 에서 연결합니다.

## 4. 권한 구조 (설계서 7장 그대로)

| 기능 | 비회원 | 준회원 | 정회원 | 재정권한 | 담임목사 |
|---|:--:|:--:|:--:|:--:|:--:|
| 공개 페이지 | ○ | ○ | ○ | ○ | ○ |
| 내 헌금 · 가정 합산 | × | × | 본인/세대주 | ○ | ○ |
| 재정관리 전체 | × | × | × | ○ | ○ |
| 교적관리 | × | × | × | ×* | ○ |
| 권한 지정 · 회원 승격 | × | × | × | × | ○ |

가입하면 먼저 **준회원**입니다. 나의 기록 화면에서 이름과 생년월일을 넣어 교적과 일치하면
**정회원**이 되고, 그때부터 본인 헌금 내역과 가정 합산이 열립니다.

이 제한은 화면에서 메뉴를 감추는 방식이 아니라 **데이터베이스의 행 단위 접근 규칙(RLS)** 으로
강제합니다. 주소창에 `finance.html` 을 직접 쳐 넣어도 권한이 없으면 숫자가 내려오지 않습니다.

\* 교적을 재정권한자에게도 완전히 닫으려면 `supabase/02_gyojeok.sql` 의 정책에서
`public.is_finance()` 를 `exists(select 1 from public.admins where uid = auth.uid())` 로 바꿔 Run 하세요.
